# 完走ゲート

残件があるのにターンが終わるのを止める。人間が一度も介在せずに完走することが、
このスキル群で最も重要な要件であり、その実体がこのゲートである。

設計の根拠は `docs/superpowers/specs/2026-08-31-人間非介在の完走ゲート-design.md`。

## いつ効くか

テストスキル（`generating-spec-tests` / `executing-spec-tests`）を起動した
**そのセッションだけ。** 装填されていないセッションでは何も止めない。

フェーズは起動したスキルで決まる。

| 起動したスキル | 完了条件 |
|---|---|
| `generating-spec-tests` | `testable` が `yes` の要件がすべて被覆されている |
| `executing-spec-tests` | `todo` が 0 件、かつ成果物ディレクトリ直下に `delivered.json`（Phase 6 の納品完了マーカー）が存在すること |

実施フェーズで要件の被覆を見ない理由: 被覆されていない要件は生成フェーズにしか
直せない。実施フェーズでいくらテストを消化しても解消しないので、そこで止め続けると
永久にブロックされる。

`fail` が残っていても完了とする。FAIL の修正はこのスキル群のスコープ外である。

## ブロックし続けない

ターン終了フックは **8 回連続でブロックすると Claude Code 側に上書きされて
ターンが終わる。**

上書きされると「残件があるのに正常終了した」ように見える。無人実行ではそれに
気づけない。だから 8 に届く前に自分から降りる。

| 上限 | 値 | 何を見ているか |
|---|---|---|
| 前進 0 のターン数 | 3 ターン | 台帳の `todo` が減らないターンが続いた回数 |
| 連続ブロック回数 | 6 回 | 前進の有無にかかわらずブロックした回数 |

どちらかに達したらブロックをやめ、失敗として読める報告を出して降りる。

**気づける失敗のほうが、気づけない成功より価値がある。**

この 2 つの数値は初期値である。環境構築に 1 ターン使うような場合、正常に作業して
いても台帳が動かない。厳しすぎると正常系を殺す。値は `constants.mjs` にあり、
最初の実行で見直す。

### 既知の限界: 2本のStopフックの連続ブロックは別々に数える

`gate-verify`(既存のセルフレビュー記録ゲート)と`testing-complete verify`(このゲート)は
独立したStopフックであり、それぞれ自分が返した`block`判定の回数だけを数えている。
Claude Code側の「8回連続ブロックで上書き」判定が実際にターン単位かフック単位かは
コードから検証できない。もし`gate-verify`が絡む形でブロックが挟まると、このゲートの
カウンタ(6回)とClaude Code実機側のカウント(8回)が想定通りに揃わない可能性がある。

初回の実運用で、`MAX_CONSECUTIVE_BLOCKS`(6)が実測でも8回未満に収まっているかを
確認すること。

## 誤ってブロックしない条件

- **バックグラウンド作業が走っている間は保留する。** テストコマンドを裏で走らせて
  いる最中は、ターンの終了ではなく待機である
- **成果物ディレクトリが見つからなければ何もしない。** まだ台帳が無い段階で止めない
- **台帳を検査できなかったら降りる。** 「まだ終わっていない」と「そもそも検査できな
  かった」を同じ扱いにすると、台帳が壊れているだけで永久にブロックし続ける

## 降りたとき

成果物ディレクトリに `stop-report.json` が残る。

```json
{
  "stopped_at": "2026-09-01T12:34:56.000Z",
  "phase": "execution",
  "reason": "前進が 3 ターン無い",
  "progress": { "total": 42, "todo": 5, "pass": 30, "fail": 5, "error": 2, "out_of_scope": 0 },
  "most_recent_attempt": {
    "case_id": "T-013",
    "status": "error",
    "attempts": "3",
    "evidence_path": "evidence/T-013/",
    "updated_at": "2026-09-01T12:30:00.000Z"
  }
}
```

このファイルがあったら、**そのテストは完走していない。** レポートの見た目が
整っていても完了として扱わない。

降りたあとは装填が消える。同じ報告を毎ターン繰り返さないためで、記録は
`stop-report.json` に残っている。

## 目標条件との併用

対話実行では、ターン終了フックに加えて目標条件も使う。条件は「台帳の `todo` が
0 件」。別の評価器が毎ターン後に条件を再検査するので、フックが想定外の挙動を
してももう片方が残る。

CI 実行では目標条件が使えない。フックだけが頼りになる。

## ゲートを外す

対話中に外したいときは、そのセッションの `session_id` を指定する。

```bash
node -e 'import("kiai-sp/lib/spec-testing/completion-state.mjs").then(m => m.disarmCompletion("<session_id>"))'
```
