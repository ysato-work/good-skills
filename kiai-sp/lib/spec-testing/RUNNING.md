# 設計書とコードの検証テストの実行方法

設計書に書かれたとおりに実装されているかを、AI が自律的に検証する。人間は起動する
だけで、テストケースの作成から実施、納品までを介在せずに完走する。

スキルは 2 本ある。

| スキル | 何をするか |
|---|---|
| `generating-spec-tests` | 設計書と差分からテストケースを作り、レビュー合議で改善して台帳に書く |
| `executing-spec-tests` | 台帳を上から逐次消化し、証跡を残し、PR まで出す |

成果物は**検証対象リポジトリ**の `docs/superpowers/testing/<spec 名ベース>/` に出る。
このリポジトリには何も残らない。

関連する文書:

- `DATA-CONTRACT.md` — 台帳と証跡の形
- `TIERS.md` — どこまでの環境を自分で立ててよいか
- `COMPLETION-GATE.md` — 完走ゲートの挙動と、詰まったときの読み方

## 対話実行

```
/generating-spec-tests docs/superpowers/specs/<設計書>.md
```

台帳ができたら次を起動する。

```
/executing-spec-tests docs/superpowers/specs/<設計書>.md
```

対話実行では、ターン終了フックと目標条件の両方が効く。片方が想定外の挙動をしても
もう片方が残る。

途中で止まったら `<artifact_dir>/stop-report.json` を見る。これがあるなら、その
テストは完走していない。

## CI 実行

**対話実行と同じスキルを、人が起動せずに走らせるだけである。** 判定も成果物も
変わらない。CI 特有なのは次の 3 点だけ。

1. **`claude -p` で 1 回の実行として走らせ、`--output-format json` で機械可読な
   出力を得る**
2. **`--allowedTools` で使えるツールを限定する。** 無人実行ではこの制限が効く
3. **対話用の目標条件が使えない。** ターン終了フックだけが完走を担保する

PR 作成のための認証情報は CI 側で用意する。

```bash
claude -p "/executing-spec-tests docs/superpowers/specs/<設計書>.md" \
  --output-format json \
  --allowedTools "Read,Write,Edit,Bash,Agent,Glob,Grep"
```

### ジョブの成否

**検査スクリプトの終了コードをそのまま使う。**

```bash
node kiai-sp/lib/spec-testing/check-progress.mjs \
  --dir docs/superpowers/testing/<spec 名ベース> \
  --phase execution
```

| 終了コード | 意味 |
|---|---|
| `0` | 全件消化した |
| `1` | 残件がある |
| `2` | 検査できなかった |

**完走の判定を CI 側で別に定義しない。** 同じ判定を 2 箇所に持つと必ず食い違う。
判定者は台帳と検査スクリプトだけである。

`fail` が残っていても検査スクリプトは `0` を返す。テストが失敗していること自体は
「テスト計画をやりきったか」とは別の話で、失敗したテストを含む PR はプロジェクト
本来の CI が赤にする。それが正しい。

## 納品されるもの

固定の 6 手順で進む。分岐も人間への問いかけも無い。

1. 検証開始時点のブランチから成果物ブランチを切る
2. テストアーティファクトをコミットする
3. テストコードをコミットする
4. 環境定義をコミットする
5. 成果物ブランチを remote に push する
6. base を検証開始時点のブランチにして PR を作成する

PR の base は**検証開始時点のブランチ**である。main ではない。検証対象が開発中の
ブランチなので、成果物の行き先もその開発ブランチになる。マージするかどうかは人間が
PR を見て決める。

投稿先は検証対象のブランチが追跡している remote から決まる。このリポジトリには
出さない。

## このスキルがしないこと

- **失敗したテストの修正。** 記録して次へ進む
- **プロジェクトの CI 設定の変更。** 追加した結合テストや E2E を CI に組み込むかは
  人間が決める。判断材料は `report.md` に書かれる
- **落ちるテストを緑にする細工。** ガードが機械的に止める
- **main へのマージ**
