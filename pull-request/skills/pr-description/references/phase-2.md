# Phase 2 — 主眼の確定とついでの切り分け

## 主眼

**主眼 = 差分全体を覆う文の集合。** 主眼の数がそのまま展開部分の文数になる。上限は 2 文である。

1. `material.md` から「この PR は何をしたのか」の候補を集める
2. 各候補が差分のどこを説明するか対応付ける
3. 覆えない差分が残ったら候補を足す

「1 文」は文字数ではなく**主眼が 1 つ**の意味。「〜をやめ、〜するようにした」は 2 つ言っているので分けるか、1 つに絞る。

PR の大きさは文数の根拠にしない。何ファイルでも主眼が 1 つなら 1 文。

**主眼が 2 つのときの順序**は、依存関係があれば前提を先に、無ければ差分の大きい方を先にする。`thrusts` 配列にこの順序で入れる。

## ついでの切り分け

「ついでにここも直した」が 1〜2 個混ざるのが普通。主眼に含めると本文が濁る。

**判定に外部の宣言は使わない。** PR タイトルは新規作成時にこのスキル自身がセットするので循環する。イシューとブランチ名は当てにならない。

**価値でも切らない。** UI 文言修正は単体で PR に値するが実際には混ざる。「単体で PR に値するか」で切ると主眼に上がってしまう。

切るのは差分の中の構造。

1. 差分を依存関係でかたまりに分解する
2. かたまりが 1 つなら、それが主眼である。typo だけの PR なら typo が主眼になる
3. 複数あるなら、各かたまりを取り除いても他が成立するかを見る。成立する小さいかたまりがついで
4. 残ったかたまりが主眼。数が 3 以上なら `概要` に畳む

手順 3 の「小さい」はかたまり同士の相対比較。**絶対値では判定しない。**

聞いているのは主観の「価値があるか」ではなく、事実の「依存があるか」である。ここを価値判断にすり替えない。

## 主眼が 3 つ以上あるとき

まず**束ねている理由を探す。** あればそれが主眼で 1 文に戻る。たとえば「リリース前の細かい直しをまとめた」である。3 つに見えていたのは粒度の取り違え。

束ねる理由が無ければ、文体は変えず 1 文 = 1 主眼で書き、`<details>` で畳む。**summary は固定文字列 `概要`。** 装飾しない。

このとき展開部分は空になる。読む順序も行コメント側にあるので、本文は fold だけになる。一目で掴めるものが無いのが事実なので、それでよい。

## 出力

`WORKDIR/thrust.json` に書き出す。

```json
{
  "thrusts": ["採点に失敗した候補を 50 で埋めるのをやめた"],
  "incidentals": [{"where": "lib/utils.mjs", "what": "未使用 import を消した"}],
  "fold_all": false
}
```

`fold_all` は主眼が 3 以上で `概要` に畳む場合に `true`。
