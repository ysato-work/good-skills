# Phase 4 — 表層検出

**表層は機械で検出する。** AI は自分の癖を認識しにくいので、禁止語や文数を LLM の主観に任せると外す。

## 装飾を消す

**絵文字と太字は検出して直させるのではなく、機械が消す。** 消しても文が成立し、読者に見えていたものが変わらないので、情報が失われない。ループの周回を装飾の直しに使わない。

表層検査より先に、**毎周回**走らせる。1 周目だけにしないのは、Phase 6 の書き直しで絵文字や太字が戻るため。

```bash
# edit モード
node <SKILL_DIR>/lib/strip-decoration.mjs \
  --body-file <WORKDIR>/body.md \
  --comments-file <WORKDIR>/line-comments.json \
  --policy <SKILL_DIR>/policy/slop.json \
  > <WORKDIR>/ledger/<実行 ID>/decoration-iter-<N>.json

# create モード
node <SKILL_DIR>/lib/strip-decoration.mjs \
  --body-file <WORKDIR>/body.md \
  --comments-file <WORKDIR>/line-comments.json \
  --title-file <WORKDIR>/title.txt \
  --policy <SKILL_DIR>/policy/slop.json \
  > <WORKDIR>/ledger/<実行 ID>/decoration-iter-<N>.json
```

スクリプトは渡したファイルを**その場で書き換える。** 出力は `{"emoji": N, "bold": M}` で、消した個数。Phase 6 の台帳に載せる。

**目視で絵文字や太字を消さない。** スクリプトを通す。

## 手順

`WORKDIR/line-comments.json` をそのまま渡してスクリプトを走らせ、**出力をファイルに保存する**。`<N>` は今の周回番号。`create` モードのときは `--title-file` も付ける。

```bash
# edit モード
node <SKILL_DIR>/lib/slop-check.mjs \
  --body-file <WORKDIR>/body.md \
  --comments-file <WORKDIR>/line-comments.json \
  --policy <SKILL_DIR>/policy/slop.json \
  > <WORKDIR>/ledger/<実行 ID>/slop-iter-<N>.json

# create モード
node <SKILL_DIR>/lib/slop-check.mjs \
  --body-file <WORKDIR>/body.md \
  --comments-file <WORKDIR>/line-comments.json \
  --title-file <WORKDIR>/title.txt \
  --policy <SKILL_DIR>/policy/slop.json \
  > <WORKDIR>/ledger/<実行 ID>/slop-iter-<N>.json
```

出力は `{"violations": [{"rule": "...", "detail": "...", "kind": "..."}], "identifiers": [{"where": "...", "token": "..."}], "parens": [{"where": "...", "token": "..."}]}`。`kind` は下の「違反は 3 つに分かれる」を参照。`identifiers` は違反ではなく Phase 5 の問い 6 の入力である。詳細は下記の「識別子の一覧は違反ではない」の節に書く。`parens` も違反ではなく Phase 5 の問い 14 の入力である。詳細は下記の「丸括弧の一覧も違反ではない」の節に書く。台帳（`iter-<N>.json`）と同じ実行 ID のディレクトリに置く。前回の実行が残した同名ファイルを今回のものとして誤って読まないようにするため。

**行コメントを書き写した別ファイルを作らない。** 投稿するのと同じ `line-comments.json` を検査する。写し間違えると未検査のコメントが投稿される。スクリプトは `{path, line, numbered, text}` のオブジェクト配列を受け取り、`numbered` フラグで番号コメントかを判定する。

**保存した `slop-iter-<N>.json` が Phase 6 のループ判定の入力になる。** 違反件数を親が数え直して台帳に書くことはしない。ファイルを作らずに実行すると Phase 6 が止まる。

## 検出するもの

| ルール | 内容 |
|---|---|
| 禁止語 | 大げさな形容・自己賛美・定型句 |
| 禁止表現 | これから誰かが何かをする話と、書き手の評価・提案。話の例は `今後` `する予定` `別途対応`、評価・提案の例は `すべき` `方がよい` である。語で見る。差分は見ない |
| 絵文字を全面禁止 | 絵文字が 1 つでもあれば違反。コードフェンスとインラインコードの中は対象外 |
| 太字を全面禁止 | 太字が 1 つでもあれば違反。コードフェンス・インラインコードの中は対象外。URL の中は下線 2 つ `__..__` は対象外だが、星 2 つ `**..**` は対象外ではない。`*` は URL の終端文字なので保護範囲に入らない |
| 展開部分の最大文数 | 既定 2 文。`。！？` に加えて**改行で区切られた行も 1 文と数える**。これは句点を打たない体言止めの羅列を通さないためである |
| 展開部分に箇条書きを禁止 | 行頭の `-` `*` `1.` |
| 展開部分にファイル名を禁止 | 拡張子付きのファイル名 |
| 展開部分に識別子を禁止 | 単語の途中に大文字が入る語・下線でつないだ語・括弧付き・点でつないだ語・バッククォート囲み |
| 展開部分に丸括弧を禁止 | 丸括弧を形で拾う。コードフェンス・インラインコード・URL・Markdown リンクの飛び先・HTML コメントの中は対象外 |
| 番号コメントは1行 | `numbered: true` のコメントに改行があれば違反 |
| detailsの中身の最小文字数 | 空虚なテンプレ節の検出 |
| PRタイトルの最大文字数 | `create` モード時のみ。既定 35 文字。値は `policy/slop.json` にある |
| 必須detailsタイトル | `変更のサマリー` が無ければ違反 |
| 任意枠の最大個数 | 予約タイトル以外の `<details>` が 3 個以上なら違反 |
| 禁止detailsタイトル | `<summary>` に `影響範囲` `今後の対応` `今後の予定` `残課題` `フォローアップ` のいずれかを含む枠があれば違反。改題では直したことにならない。枠ごと削除する |
| 1段階目の最大バイト数 | `テスト` の枠を除いて、子を持つ 1 段階目が 21 バイト超。1 段だけの項目は対象外 |
| 構造化箇条書きの段 | 同上 4 段階目があれば違反 |
| 1段階目に2段階目が無い | 同上、見出しの直下が 2 段階目でない |
| 構造化箇条書きが無い | 同上、`- ` が 1 行も無い |
| detailsの中身の最大バイト数 | 構造化対象と任意枠が 750 バイト超。`ドキュメント` と `概要` は対象外 |

## 違反は 3 つに分かれる

出力の各違反には分類（`kind`）が付く。**分類ごとに扱いが違う。**

| 分類 | 中身 | 扱い |
|---|---|---|
| 装飾 | 絵文字、太字 | 上の除去で消えているはずのもの。ループにも投稿ゲートにも数えない。ここに出たら除去にバグがあるので報告する |
| 骨格 | 必須の枠が無い、枠の中身が空、必須の枠に箇条書きが無い、1 段階目に 2 段階目が無い、禁止表現 | ループで直す。上限に達して残っていたら**投稿しない** |
| 言い換え | 上の 2 つ以外の全部 | ループで直す。上限に達して残っていても**投稿する** |

**分類を親が付け直さない。** スクリプトの出力の値をそのまま使う。分類の表に無いルールが出るとスクリプトがエラーで止まる。

**バッククォート囲みは中身が何であれ拾う。** 日本語の句でも識別子として報告する。見せる 1〜2 文でコード書式を使わせないため。

展開部分に識別子が複数あっても違反は 1 件で、`detail` に語を全部並べる。**並んだ語は全部直す。** 1 語ずつ直すと残りが次の周回まで見えず、`max_iter` を使い切る。

## 識別子の一覧は違反ではない

出力には `violations` の他に `identifiers` が入る。`<summary>` と `<details>` の中身、行コメントから拾った語の一覧で、**違反ではない。** Phase 5 の問い 6 の入力になる。

```json
{
  "violations": [{"rule": "展開部分に識別子を禁止", "detail": "\"applyFallback\" がある", "kind": "言い換え"}],
  "identifiers": [{"where": "summary 1", "token": "partitionByThreshold"},
                  {"where": "details 1", "token": "applyFallback"},
                  {"where": "行コメント 3", "token": "enabled_features"}]
}
```

一覧を違反にしない理由が 2 つある。

- **初出に説明が付いているかは機械には見えない。** 意味の理解が要るので Phase 5 に渡す
- **一覧を違反にするとループの周回を食いつぶす。** Phase 6 は表層違反に `keep` を認めない。全件直す。許可語リストから漏れた一般語が違反として出るたび、直せない違反が毎周回出続けて、軽量 3・本気 4 の `max_iter` まで埋まる。「展開部分に識別子を禁止」は分類上`言い換え`なので、実際には上限に達しても報告した上で投稿はされるが、周回を無駄に消費すること自体は避けたい

`where` は `summary <N>`・`details <N>`・`行コメント <N>` の 3 種類。`summary` と `details` は同じブロックでも別扱いで、summary は畳んだ状態で見える行なので分けている。

一覧は**初出だけ**載る。同じ語の 2 回目以降は載らない。問い 6 が見るのは初出の説明の有無だから。

`identifiers` はループ判定に影響しない。`loop-decide.mjs` は `violations` を分類（`kind`）で絞り込み、`骨格` と `言い換え` の件数をそれぞれ数える。**装飾の違反は数えない。**

## 丸括弧の一覧も違反ではない

出力には `violations` と `identifiers` の他に `parens` が入る。`summary` と
`details` の中身、行コメントから拾った丸括弧の一覧で、**違反ではない。** Phase 5 の
問い 14 の入力になる。

```json
{
  "violations": [{"rule": "展開部分に丸括弧を禁止", "detail": "\"（42 件）\" がある", "kind": "言い換え"}],
  "parens": [{"where": "summary 1", "token": "（必須）"},
             {"where": "details 1", "token": "（テスト）"},
             {"where": "行コメント 3", "token": "（他スキルが通っているため）"}]
}
```

一覧を違反にしない理由は `identifiers` と同じである。例外に当たるかどうかは機械には
判定できない。加えて、一覧を違反にすると直せない違反が毎周回残り、周回を無駄に消費
する。「展開部分に丸括弧を禁止」は分類上`言い換え`なので、実際には上限に達しても
報告した上で投稿はされるが、周回を無駄に消費すること自体は避けたい。

`identifiers` との違いが 2 つある。**丸括弧は初出に限らず、出現ごとに全部載る。**
1 つずつ直す対象なので、初出だけでは直し漏れる。**展開部分の丸括弧は一覧に載らない。**
展開部分は `violations` の側で見ているので、二重に数えないためである。

`where` は `summary <N>`・`details <N>`・`行コメント <N>` の 3 種類である。

## 機械では取れないもの

`Vendor` のような大文字始まりの英単語 1 語は機械の担当外。`PR` `AI` `DB` `GitHub` と形が同じで区別できない。`pr-review` のようなハイフン区切りの名前とリポジトリ固有の日本語の造語も、5 つの語形のどれにも当たらないので取れない。**Phase 5 の問い 6 で見る。**

コードフェンスで囲んだ部分・URL・拡張子付きファイル名も識別子として拾わない。コードは散文ではなく、ファイルパスは読めば分かる。展開部分のファイル名は既存の `展開部分にファイル名を禁止` が見ている。

## やらないこと

- **目視で禁止語を探さない。** スクリプトの出力だけを違反とする
- 出力された違反を「これは偽陽性だ」と親の判断で落とさない。**表層違反は理由を書いても残せない。** Phase 6 で `fixed` 以外の決着を認めていないためである。全件直す
- **装飾の違反を親が消さない。** 除去スクリプトが消す。ここに出たのはバグの合図なので、報告して先に進む
- policy を実行中に書き換えない

## 「証拠のない断定」はここで見ない

「テスト済み」「確認済み」「問題ありません」は禁止語に入れていない。機械では証拠の有無が見られず、語として禁止すると根拠付きで書く正当なケースまで弾く。**Phase 5 の問い 5 で見る。** 問い 5 は差分との食い違いを扱う。

## 未来の予定と評価は語で見る

「〜する予定」「〜すべき」は語の形で見分けられる。直し方はその文を消すことで、消せば必ず成立するので、機械で検出して `骨格` に置ける。

現在形の動作説明は対象にしない。「3 回まで再試行して超えたら止める」はコードの今の動きであって予定ではない。予定数量・返品方針のような業務の名詞も対象にしない。これは現場の語を違反にしないため。

**一覧が境界。** `するべき` `ほうがよい` `ほうがいい` のような変種は機械では拾えない。取りこぼしは問い 13 が拾う。
