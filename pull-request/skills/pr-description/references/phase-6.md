# Phase 6 — 台帳・修正・ループ判定

## スキップは絶対に禁止

Phase 4 の違反と Phase 5 の指摘を、親の判断で落としてはいけない。以下はすべてスキップの言い訳であり、認めない。

- 「これは偽陽性だ」
- 「もう対応済みだ」
- 「直すとかえって分かりにくくなる」
- 「機械的な修正に落とせない」
- 「軽微なので次回で良い」

語り口の指摘も同じ。足切りを通った指摘を「AI が書いたのだから当然だ」と落とさない。落としてよいものはスクリプトが既に落としている。

## 決着のさせ方は 4 種類で違う

| 指摘の出どころ | 認める決着 |
|---|---|
| **表層違反**。Phase 4 のスクリプトが出した `violations` を指す | `fixed` **だけ**。理由を書いても `keep` にできない |
| **構造指摘**。Phase 5 のセルフレビュー 14 問を指す | `fixed`、または `reason` を書いた `keep` |
| **語り口の指摘**。Phase 5 の判定役の指摘のうち足切りを通ったものを指す | `fixed` **だけ**。上限も無いので全件直す |
| **圧縮の指摘**。Phase 5 の親のチェックと圧縮担当の指摘のうち門を通ったものを指す | `fixed`、または `reason` を書いた `keep` |

**圧縮の指摘に理由付きの `keep` を認めるのは、「冗長かどうか」に読み手の判断が入るため。** 縮めると因果が読めなくなる箇所は実際にある。ただし**理由を書かずに落とすことは認めない。** 親のチェックで挙げた箇所と圧縮担当の指摘は、どちらも同じこの扱いにする。出どころで区別しない。

**圧縮の指摘はその周回で決着させる。** 圧縮は前半の周回だけ走るため、決着させずに次の周回へ持ち越すと、次周回には `compress` の記録自体が無くなり、未決着だった指摘が数から消えてしまう。

**語り口の指摘に `keep` を認めない。** 引用が本文に実在することはスクリプトが確かめているので、指摘の存在自体に解釈の余地が無い。上限も置いていないので、通った指摘は全件直す。

**ただし書き直しは言い方だけ。** 事実を足さない、消さない。語り口を整えるつもりで差分にない主張を書くと、14 問の中で最も重い「本文と行コメントが差分と食い違っていないか」に触れる。書き直した文は次の周回でその問いを通り直す。下記のループ判定が続行を強制する。

**表層違反に `keep` を認めない。** 禁止語・文数・箇条書き・ファイル名・展開部分の識別子・展開部分の丸括弧・絵文字・番号コメントの改行は、機械が事実として検出したもので、解釈の余地がない。「文脈上必要」「これは偽陽性」と書けば通る経路を残すと、判定が親の作文になる。直せないなら本文の側を変える。

構造指摘だけ理由付きの `keep` を認めるのは、問い 6 以外の問いが読み手の判断を含み、直すと主眼が差分を覆えなくなるような場合が実際にあるため。それでも**理由を書かずに落とすことは認めない。**

**問い 6 の指摘は例外で、`keep` の理由を 2 つに限る。** 認めるのは「初出に説明が付いている」と「リポジトリの外でも通じる語である」のどちらかだけ。どちらも本文と差分を見れば確かめられる事実で、読み手の判断を含まない。

「読者は知っているはず」「レビュワーはエンジニアなので分かる」は理由として認めない。読者がその語を知っているかは判定できない。Phase 3 に書いてあるので、これを認めると判定が親の作文になる。**機械が識別子の一覧を違反にしていないのは、ループが詰まるのを避けるためであって、判断を親の裁量に委ねたからではない。**

**問い 14 の指摘も例外で、`keep` の理由を 1 つに限る。** 認めるのは「論理名から物理名への短い言い換えになっている」だけである。本文と差分を見れば確かめられる事実で、読み手の判断を含まない。「文脈上必要」「読みにくくなる」は理由として認めない。

丸括弧の指摘を機械の違反にしていないのは、ループが詰まるのを避けるためであって、判断を親の裁量に委ねたからではない。

表層違反の件数は台帳から読まない。Phase 4 が保存した `WORKDIR/ledger/<実行 ID>/slop-iter-<N>.json` の `violations` 配列を、`loop-decide.mjs` が分類 `kind` 別に数える。数えるのは `骨格` と `言い換え` だけで、`装飾` は数えない。台帳に何と書いても投稿ゲートは動かない。

語り口の指摘の場所も台帳には無い。Phase 5 が足切り後に書いた `WORKDIR/ledger/<実行 ID>/tone-kept-iter-<N>.json` を Read する。`kept` は残った指摘の配列で、これが Phase 6 で直す対象である。`dropped` は捨てた指摘とその理由で、台帳の `entries` に記録として残すだけで直さない。圧縮の指摘の場所も台帳には無い。Phase 5 が門を通した後に書いた `WORKDIR/ledger/<実行 ID>/compress-kept-iter-<N>.json` を Read する。`kept` が直す対象、`dropped` は記録として残すだけで直さない。

## 前回までの実行の台帳を読む

台帳を書く前に、`WORKDIR/ledger/` にある**今回以外の実行 ID のディレクトリ**を見る。あれば直近の実行の `iter-<N>.json` を Read する。N が最大のものを選ぶ。

- 同じ構造指摘が前回すでに `keep` で決着していないか確認する
- 同じ指摘を同じ理由で再び `keep` にする場合は、その旨を今回の `reason` に書く。書く内容は「前回の実行でも同じ理由で残した」である。
- 前回 `keep` にした理由が今回は成り立たないなら `fixed` にする

`WORKDIR` が 2 階層目に日時ではなく PR 番号を使っているのは、この読み直しのため。**前回の台帳を消さない。**

## 台帳

`WORKDIR/ledger/<実行 ID>/iter-<N>.json` に 1 周回 1 ファイルで残す。`<実行 ID>` は `WORKDIR/run-id` の中身である。Phase 0 で決めた `YYYYMMDD-hhmmss` を指す。

```json
{
  "iter": 1,
  "review_findings": 0,
  "tone": {"findings": 1, "rewritten": 1, "unresolved": 0, "dropped": 1},
  "compress": {"findings": 4, "applied": 3, "kept_with_reason": 1, "unresolved": 0, "dropped": {"gate1": 1, "gate2": 0, "gate3": 0}},
  "decoration": {"emoji": 1, "bold": 4},
  "entries": [
    {"source": "slop", "finding": "禁止語: 自己賛美 \"改善しました\"", "action": "fixed", "reason": ""},
    {"source": "review", "finding": "問い 2: 何をしたのかが復元できない", "action": "keep", "reason": "主眼を変えると差分を覆えなくなる"},
    {"source": "tone", "finding": "展開部分 \"大幅に改善されました\": 誇張した形容で中身が無い", "action": "fixed", "reason": ""},
    {"source": "tone", "finding": "任意枠 \"移行の順序\": 落とした。引用が本文に無い", "action": "dropped", "reason": "引用が本文に無い"},
    {"source": "compress", "finding": "テスト \"リトライの上限で確実に停止することを確認した\": 冗長", "action": "fixed", "reason": ""}
  ]
}
```

| キー | 中身 |
|---|---|
| `iter` | 今の周回番号。**記録用。** ループ判定はこの値を読まず、台帳ファイルの個数を数える |
| `review_findings` | Phase 5 の指摘のうち、**まだ決着していない件数**。`fixed` と理由付き `keep` はどちらも決着なので数えない |
| `entries` | 指摘 1 件 1 要素。`source` は `slop`、`review`、`tone`、`compress` の 4 つで、それぞれ表層、構造、語り口、圧縮を指す。`action` は `fixed`、`keep`、`dropped` の 3 つ。`slop` に `keep` は書けない。`dropped` は `tone` の指摘が足切りで落ちたこと、または `compress` の指摘が門で捨てられたことを記録として残す場合だけに使う。使う場面は下の「語り口の指摘 1 件ごとの内容を `entries` に残す」の説明と同じである |
| `tone` | 語り口の判定の結果。`findings` は足切りを通った件数、`rewritten` は書き直した件数、`unresolved` は直さず残した件数である。`keep` を認めていないので `unresolved` は 0 でなければならない。0 以外を書くと `loop-decide.mjs` が例外を投げて止まる。`dropped` は引用の門で捨てた件数である。門は「引用が無い」「引用が本文に無い」「名指しの枠が入力に無い」の 3 つ。**「AI っぽくない」と判定されて捨てた件数はここに含めない**。この件数には `filter-tone.mjs` の `counts.dropped` の値をそのまま入れる。`counts.not_ai_like` は台帳に書かない。**判定を走らせていない周回では `tone` キーを書かない。** これは省略可ではなく必須である。前周回の値を写せてしまうと、書き直しが 0 件の周回でも `tone.rewritten` が残り続けて上限まで無駄に回る。**足切りスクリプトの出力の `kept` は残った指摘の配列で、台帳側で使う名前とは別物なので、台帳側で `kept` という名前を使わない** |
| `compress` | 圧縮の結果。`findings` は門を通った件数で、**圧縮担当の分だけ**を数える。`applied` と `kept_with_reason` と `unresolved` は親のチェック分も含むため、単純な足し算では合わない。`applied` は縮めた件数、`kept_with_reason` は理由を書いて残した件数、`unresolved` はまだ決着していない件数で、残りの件数に足される。`dropped` は門ごとに捨てた件数で、`filter-compress.mjs` の `counts` の `gate1` と `gate2` と `gate3` をそのまま入れる。**軽量モードは門が無いので、軽量モードの `findings` には親が挙げた件数を書き、軽量モードの `dropped` は 3 つすべて 0 を書く。圧縮を走らせた周回なら記録自体は必ず書く。** **圧縮を走らせていない周回では `compress` キーを書かない。** これは省略可ではなく必須である。前周回の値を写せてしまうと、反映が 0 件の周回でも `compress.applied` が残り続けて上限まで無駄に回る。**`applied` は親が台帳に書く自己申告の数値で、台帳の構造上は裏取りできない**。この性質は `tone.rewritten` と同じである。虚偽の申告は「スキップは絶対に禁止」の対象として扱う |
| `decoration` | Phase 4 の除去スクリプトが消した個数。`decoration-iter-<N>.json` の中身をそのまま入れる |

**語り口の件数を `review_findings` に混ぜない。** `review_findings` は 14 問の未決着だけを数える。混ぜると語り口の指摘が投稿ゲートに載ってしまう。

**語り口の指摘 1 件ごとの内容を `entries` に残す。** 枠・引用・理由・直したかどうかを書く。あとから「同じ語が何度も出ている」に気づくための材料で、これがログとしての蓄積になる。**判定役には渡さない。** 何度も出る語に気づいたら、人が `policy/slop.json` の禁止語に手で足す。以降は機械が取る。

`review_findings` が欠けているか数値でないと `loop-decide.mjs` が例外を投げて止まる。

**`tone.rewritten` は `review_findings` と同じく、親が台帳に書く自己申告の数値である。** 書き直した後にここへ `0` と書けば、書き直した文を表層検査と 14 問に通し直す続行の強制を素通りできる。強制の内容は下記のループ判定に書いてある。台帳の構造上、書いた値の裏取りはできない。この性質は変えない。虚偽の申告は「スキップは絶対に禁止」の対象として扱う。

上の例は表層違反と構造指摘はすべて決着しているが、`tone.rewritten` が 1 件、`compress.applied` が 3 件残っているので、次のループ判定は `clean` ではなく `CONTINUE` になる。書き直した文と縮めた文を表層検査と 14 問にもう 1 回通すため、決着済みの指摘が無くても周回を続ける。どちらか片方だけでも続行の理由になる。

## 修正

`action: "fixed"` にした指摘を本文と行コメントに反映する。反映先は `WORKDIR/body.md` と `WORKDIR/line-comments.json`。

表層違反は全件がここに来る。`keep` が無いためである。反映しないまま次の周回に進むと、Phase 4 が同じ違反を再び出して `iter` だけが進む。投稿を止めるのは骨格の違反とセルフレビューの未決着だけで、言い換えの違反は報告した上で投稿される。

## ループ判定

**判定を親がやらない。** スクリプトに委譲する。

```bash
node <SKILL_DIR>/lib/loop-decide.mjs --workdir <WORKDIR>
```

スクリプトは自分で材料を集める。親が数値を渡す口は無い。

- `iter` — `WORKDIR/ledger/<実行 ID>/iter-<N>.json` の個数
- `mode` — `WORKDIR/level.txt`。`light` か `serious` のどちらかである
- `skeleton` — `slop-iter-<iter>.json` の違反のうち分類が `骨格` のもの
- `reword` — 同じく分類が `言い換え` のもの
- `review_findings` — `iter-<iter>.json` の値
- `tone_rewrites` — `iter-<iter>.json` の `tone.rewritten`。無ければ 0
- `compress_unresolved` — `iter-<iter>.json` の `compress.unresolved`。無ければ 0
- `compress_applied` — `iter-<iter>.json` の `compress.applied`。無ければ 0

材料を集める際、`tone.unresolved` が書かれていて 0 以外なら `loop-decide.mjs` はここでエラーを投げて止まる。台帳の主張の矛盾を検出するためである。矛盾とは、`keep` を認めていないのに指摘が未決着で残っているという主張を指す。

残りの件数は `骨格の違反 + 言い換えの違反 + 14 問の未決着 + 圧縮の未決着`。装飾の違反は数えない。機械が消すためである。語り口の指摘の残りも数えない。`keep` を認めていないためである。

**圧縮の未決着は投稿を止めない。** 冗長な本文は読めるので、言い換えの違反と同じ扱いにする。骨格が欠けた本文や差分と食い違う本文とは釣り合いが違う。投稿の条件は `骨格の違反が 0 かつ 14 問の未決着が 0` のまま変えない。

| 出力 | 次の挙動 |
|---|---|
| `{"action":"CONTINUE"}` | `iter` を 1 増やして Phase 4 に戻る |
| `{"action":"STOP","publish":true,"reason":"clean"}` | Phase 7 へ |
| `{"action":"STOP","publish":true,"reason":"max_iter_reached_publishable"}` | Phase 7 へ。**残った言い換えの違反を報告する** |
| `{"action":"STOP","publish":false,"reason":"max_iter_reached"}` | **投稿しない。** 残った違反を報告し、生成物を `WORKDIR` に残して終了する |

必要なファイルが無いとスクリプトはエラーで止まる。**止まったら握りつぶさず、足りないファイルを作ってから再実行する。**

`max_iter` は軽量モードで 3、本気モードで 4。スクリプトの定数で、台帳や引数から上書きできない。本気モードだけ 1 多いのは、語り口の判定と圧縮の検査が 1〜2 周目に入って検査対象が増えるため。「収束した」「品質が上がった」のような主観的な終了判定はしない。

**語り口の書き直しをした周回と、圧縮を反映した周回の後は、残りが 0 件でも続行する。** 書き直した文と縮めた文を表層検査と 14 問にもう 1 回通すため。どちらも前半だけの軸なので、この強制が効くのは本気モードで 1〜2 周目の後、軽量モードで 1 周目の後だけ。

**この強制が上限を食い潰すことはない。** 本気モードの上限は 4 で、強制がかかるのは 2 周目の後まで。3 周目に残りが 0 になればそこで綺麗に抜ける。軽量モードは上限 3 で、強制がかかるのは 1 周目の後だけ。

上限に達したときに投稿するかは分類で決まる。**骨格の違反かセルフレビューの未決着が残っていたら投稿しない。** 必須の枠が欠けた本文、中身の空の枠が付いた本文、これから誰かが何かをする話や書き手の評価が混ざった本文は、出すのが目的に反する。**言い換えの違反や圧縮の未決着だけが残っているなら投稿する。** 禁止語 1 個や決着していない圧縮の指摘が残った本文は読めるので、出さない方がマシな状態ではない。

**語り口の指摘が残っていることは、投稿を止める理由にしない。** AI っぽい本文は、投稿しない方がマシな本文ではない。
